# regiongbi-ops — почтовый ящик между облачной сессией и сервером

Приватный репозиторий. Прямого канала между облачной сессией Claude и сервером
нет: SSH из контейнера закрыт наружу. Обе стороны видят только этот
репозиторий, через него и общаются.

```
inbox/      задания серверу        ← кладёт облачная сессия
outbox/     отчёты о выполнении    ← кладёт сервер
done/       выполненные задания    ← переносит сервер
packages/   пакеты публикации: JSON и вспомогательные файлы
tools/      публикаторы и утилиты, которые уезжают на Бегет
state/      текущее состояние сайта, обновляет сервер
AGENTS.md   постоянная инструкция исполнителя — читать в начале каждого запуска
```

## Кто что делает

**Облачная сессия.** Пишет тексты, собирает пакеты, проверяет сайт снаружи
через браузер, кладёт задания в `inbox/`, читает `outbox/`. На сервер не
заходит и на Бегет не ходит — физически не может.

**Сервер.** Забирает задания, выполняет их на Бегете по SSH-ключу, снимает
бэкапы, проверяет результат, пишет отчёты. Инициативы не проявляет: делает
то, что в `inbox/`, остальное описывает в отчёте.

**Владелец.** Читает `outbox/` когда захочет. Решает всё, что связано с
деньгами, удалением, доменом и чужими проектами.

## Правило одного писателя

Одновременно сайт правит кто-то один. Перед заливкой сервер создаёт
`state/LOCK` с меткой времени и своим номером задания, после — удаляет.
Если `LOCK` старше двух часов — считать зависшим, написать об этом в отчёт
и снять.

## Задержка

Сервер смотрит `inbox/` по расписанию, раз в 10–15 минут. Мгновенного диалога
нет и не нужно: задачи здесь не диалоговые.

## История

Каждое действие остаётся коммитом. Это не бюрократия: именно история
позволяет через неделю понять, после какой правки что сломалось, и не
полагаться на память сторон.
