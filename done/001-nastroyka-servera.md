# Задание 001 — доделать настройку сервера

Приоритет: первый. Пока не выполнено, остальные задания не берём.

`bootstrap.sh` 04.09.2026 уже отработал: файрвол, fail2ban, автообновления,
вход по паролю выключен, пользователи `zhbi` и `stocks` заведены, каталоги
`/srv/regiongbi/{repo,backups,logs,tmp}` созданы, ключ к Бегету сгенерирован
и добавлен в `~/.ssh/authorized_keys` аккаунта `pkfgbi8c`. Связка проверена:
`wp core version` с сервера возвращает `7.1`.

Осталось разложить рабочие части.

## Что сделать

1. **Настройки.** Скопировать `/root/server/config.env.example` в
   `/srv/regiongbi/config.env`, владелец `zhbi`, права 640. Заполнить одну
   строку: `BEGET_HOST=pkfgbi8c.beget.tech`. Остальное уже проставлено.

2. **Скрипты.** Разложить `/root/server/bin/*.sh` в `/srv/regiongbi/bin/`,
   владелец `zhbi`, права 750.

3. **Первый бэкап вручную**, чтобы увидеть результат, а не поверить в него:
   `sudo -u zhbi bash /srv/regiongbi/bin/backup.sh`
   Должен закончиться строкой вида «готово: база N МБ, файлов в архиве N,
   mu-плагинов N». Если упал — читать сообщение, скрипт говорит, на чём.

4. **Проверка сайта:** `sudo -u zhbi bash /srv/regiongbi/bin/monitor.sh -v`

5. **Расписание:** `sudo -u zhbi crontab /root/server/crontab.zhbi`,
   затем `sudo -u zhbi crontab -l` — убедиться, что встало.
   Бэкап в 3:20, проверка сайта в 8:40, контроль свежести бэкапа по
   понедельникам в 9:15. Время московское.

6. **Снять первое состояние** в `state/site.json`: версия ядра, число
   mu-плагинов, число опубликованных страниц и записей, дата последнего
   бэкапа, результат внешней проверки.

## Проверка результата

- `crontab -l` под `zhbi` показывает три строки;
- в `/srv/regiongbi/backups/<сегодня>/` лежит дамп базы больше 1 МБ;
- `monitor.sh -v` отработал без строк «ПРОБЛЕМА».

## Чего не делать

Ничего сверх списка. Веб-сервер, базу и второй проект (`/srv/stocks`) не
настраивать — это не наша задача.
