# Задание 009 — вернуть главный товар в разметку восьми страниц

Приоритет: первый. Правка кода mu-плагина, значит бэкап и `deploy.sh`.

## Что не так

По итогам 003: у восьми страниц с `type=list` в разметку уходят только `items`
— соседние марки, — а сам товар страницы не отдаётся никуда. Имя и цена лежат
в корне меты `_rz_product` и в HTML не попадают.

Из-за этого страница `/catalog/koltsa-kolodeznye-ks/ks-10-9/` заявляет
поисковику КС 10-5, КС 10-6 и КС 10-10, но не КС 10-9. Адрес про одно, разметка
про другое — для Google это несоответствие, и расширенный сниппет он не
покажет ни по одной из марок.

Затронуты ровно эти восемь:

```
/catalog/koltsa-kolodeznye-ks/ks-10-9/
/catalog/koltsa-kolodeznye-ks/ks-15-9/
/catalog/fbs-bloki/fbs-24-4-6/
/catalog/plity-perekrytiya-kanalov-vp/vp-18/
/catalog/opornye-plity-op/op-1d/
/catalog/opornye-plity-op/op-1k/
/catalog/lestnicy-dlya-kolodcev/skoby-hodovye/
/catalog/lestnicy-dlya-kolodcev/promyshlennye-lestnicy/
```

## Что сделать

Править `mu-rz-product-schema.php` — тот, что уже стоит. Новый плагин не
заводить: два плагина, пишущих в один и тот же узел схемы, дадут два графа.

Для `type=list` отдавать:

1. **`Product` для товара самой страницы** — из корня меты (`name`, `sku`,
   `description`, `image`, `price`). Если `price` в корне заполнен — с `offers`,
   как у обычной карточки; если пуст — без `offers`. Пустую цену не выдумывать
   и не подставлять из `items`.
2. **`ItemList` с `items`** — как сейчас, ничего не ломая. Это соседние марки,
   они полезны.

То есть на странице должно стать: один `Product` про её собственный товар плюс
`ItemList` про ряд. Сейчас первого нет вовсе.

Схему добавлять **только через фильтр `rank_math/json_ld`**, как уже сделано.

## Проверка результата

По сырому HTML, а не разбором графа:

- на всех восьми адресах появился `Product` с `name`, совпадающим с товаром
  страницы (`КС 10-9` на `ks-10-9`, `ФБС 24-4-6` на `fbs-24-4-6` и так далее);
- `offers` появился там, где в мете есть цена; там, где цены нет, `offers`
  по-прежнему отсутствует — и это правильно;
- `ItemList` на месте, число элементов не изменилось;
- прочие 137 карточек `single` не затронуты: число блоков `Product` с `offers`
  по сайту выросло ровно на столько, у скольких из восьми есть цена, и ни на
  один больше. Пересчитать тем же скриптом, что делал `product-audit.csv`,
  и приложить новые числа в отчёт.

## Отдельно, не чинить

Четыре карточки без цены (`vl-2`, `kl`, `lp-8-1`, `kksr-3`) остаются без
`offers`: цены нет ни в тексте страницы, ни в мете. Это работа владельца —
дописать цену в текст, а не наша выдумка.
