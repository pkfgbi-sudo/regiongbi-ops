
Прежняя копия сохранена: `/srv/regiongbi/tmp/deploy.sh.do-035`. Права не
изменились (`-rwxr-x---`), заливка задания шла уже синхронизированной копией —
каталоги бэкапов вышли с временем в имени.

Заодно сверил **все** файлы `bin/`: `agent-cycle.sh`, `agent-run.sh`,
`backup.sh`, `deploy-plugin.sh`, `monitor.sh`, `notify.sh`, `rz-kalitka.sh` —
совпадают с репозиторием байт в байт. Расходился только `deploy.sh`.

**Копия нужна, отдельной ей быть зачем.** Две причины:

1. `crontab` зовёт именно её — `/srv/regiongbi/bin/backup.sh`,
   `monitor.sh`, `agent-run.sh`. Если сюда же перевести запуск из `repo/`,
   ночной бэкап будет зависеть от состояния рабочего дерева, которое правит
   исполнитель.
2. `deploy.sh` на шаге 1 делает `git reset --hard origin/main` — то есть
   перезаписывает файлы в `repo/`, включая **сам себя, пока bash его читает**.
   Bash читает скрипт по мере исполнения, и подмена файла на лету может
   выполнить не тот код. Сегодня обошлось только потому, что содержимое
   совпадало с `origin`.

Поэтому предлагаю в регламент не «запускать только из repo», а обратное:
**запускать `deploy.sh` и `deploy-plugin.sh` только из `/srv/regiongbi/bin/`, а
после правки чего-либо в `repo/bin/` — копировать файл в `/srv/regiongbi/bin/` в
том же задании**. Формулировку в `AGENTS.md` сам не вписывал: задание просило
только «сказать об этом», а раздел 3.9 и правило про копию — это регламент, его
пишет владелец или облачная сессия.
